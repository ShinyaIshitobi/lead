# lead/expert/ ディレクトリ詳解

このドキュメントでは、LEAD プロジェクトの `lead/expert/` ディレクトリについて解説します。
このディレクトリには、CARLA シミュレータ上で動作する「特権エキスパート（privileged expert）」の実装が含まれています。
特権エキスパートとは、シミュレータの内部情報（他車両の位置・速度、信号状態など）に直接アクセスできるエージェントです。
自動運転モデルの学習データ（教師データ）を生成する役割を担います。

対象読者: E2E（End-to-End）自動運転の初学者

---

## 学習トピック

このディレクトリのコードを理解するために、以下のトピックを事前に学んでおくと効果的です。

- CARLA シミュレータの基本概念（ワールド、アクター、センサー、シナリオ）
- 自動運転における制御量（throttle / brake / steer）の意味
- PID 制御の基礎（比例・積分・微分制御）
- BEV（Bird's Eye View）マップの概念
- キネマティック自転車モデル（Kinematic Bicycle Model）
- IDM（Intelligent Driver Model）による車間距離制御
- OpenDRIVE フォーマット（道路ネットワーク記述）
- センサーキャリブレーション（内部パラメータ・外部パラメータ）
- Apache Arrow フォーマット（構造化データの列指向保存形式）

## クラス階層

エキスパートのクラスは以下の継承関係を持っています。

```
Expert
  └── ExpertData
        └── ExpertBase
              └── BaseAgent
                    └── AutonomousAgent (CARLA 提供の基底クラス)
```

最下層の `AutonomousAgent` は CARLA が提供する抽象クラスで、シミュレータとの通信インターフェースを定義しています。
各クラスが段階的に機能を追加していく設計になっています。

- `AutonomousAgent`: CARLA との通信インターフェース
- `BaseAgent`: エージェントの基本機能
- `ExpertBase`: ステップカウンタ、保存パス、シナリオ管理などの基盤プロパティ
- `ExpertData`: センサー構成の定義とデータ収集パイプライン
- `Expert`: 主要な運転ロジック（制御計算、シナリオ対応）

## expert.py - 主要な運転ロジック

`expert.py` はエキスパートの中核ファイルです。シミュレータの特権情報を使って、各タイムステップで適切な制御量（throttle / brake / steer）を計算します。

### run_step()

メインの制御ループのエントリーポイントです。毎フレーム呼び出され、制御コマンドを返します。

### _get_control()

実際の制御量を計算するメソッドです。以下の処理が順番に実行されます。

1. privileged_route_planner によるルート計画
   - 特権情報を使い、エゴ車両の経路上のウェイポイントや交通標識の情報を取得します。

2. 目標速度の計画
   - 速度制限、見通し距離、交差点の有無を考慮して目標速度を決定します。

3. _solve_obstacle_scenarios()
   - 駐車車両や事故車両などの静的障害物への対応ロジックです。
   - 回避経路の計算や減速判断を行います。

4. _solve_vulnerable_vehicles_scenarios()
   - 歩行者や自転車に対する緊急ブレーキのロジックです。
   - VRU（Vulnerable Road User: 脆弱な道路利用者）に対して安全距離を確保します。

5. _solve_general_scenarios()
   - 停止標識、信号機、車線変更など、一般的な交通シナリオへの対応です。
   - シナリオの種類に応じて IDM パラメータを切り替えます。

6. 特殊ケースの処理
   - 対向車両の優先判定
   - 後方衝突回避
   - カットイン（他車両の割り込み）対応

7. 横方向制御と縦方向制御
   - 横方向: PID 制御によるステアリング計算
   - 縦方向: 目標速度に追従するための throttle / brake 計算

### is_two_ways_overtaking_path_clear()

対向車線を使った追い越しの安全性を確認するメソッドです。対向車線に十分な空きがあるかを判定します。

### シナリオ対応

合計 48 種類のシナリオタイプに対して個別の処理ロジックが実装されています。各シナリオは CARLA のシナリオランナーから通知され、エキスパートはそれに応じた運転行動を選択します。

## expert_data.py - データ収集

`expert_data.py` はセンサー構成の定義と、収集データの保存処理を担当します。

### sensors()

センサーリグ（搭載センサー群）を定義するメソッドです。以下のセンサーが含まれます。

- RGB カメラ（複数台）
- インスタンスセグメンテーションカメラ
- 深度カメラ
- セマンティックセグメンテーションカメラ
- LiDAR（レーザー点群センサー）
- レーダー
- IMU（慣性計測装置）
- GPS

### tick()

各タイムステップでセンサーデータを順次処理するメソッドです。処理順序は以下の通りです。

```
RGB → インスタンスセグメンテーション → 深度強化 → セマンティクス → 点群 → バウンディングボックス → BEV
```

この順序は依存関係に基づいています。例えば、深度強化にはインスタンスセグメンテーションの結果が必要です。

### save_sensors()

センサーデータの非同期保存を行います。Python の `threading.Queue`（最大サイズ 100）を使い、メインスレッドをブロックせずにディスクへ書き込みます。

### カメラ摂動（perturbation）

データ拡張のために、カメラ位置にランダムな摂動を加える機能があります。

- 並進（translation）: 0.1〜1.0m
- 回転（rotation）: 5〜12.5度

これにより、モデルの汎化性能を高めるための多様なデータが生成されます。

### 保存ディレクトリ構成

```
rgb/           - RGB カメラ画像
depth/         - 深度マップ
semantics/     - セマンティックセグメンテーション
lidar/         - LiDAR 点群データ
radar/         - レーダーデータ
bboxes/        - バウンディングボックス
hdmap/         - HD マップ（BEV 表現）
metas/         - メタデータ
```

## expert_base.py - 基盤プロパティ

`expert_base.py` は `ExpertBase` クラスを定義し、以下の基盤機能を提供します。

- ステップカウンタ: 現在のシミュレーションステップ数を追跡
- 保存パス: データ保存先のディレクトリパス管理
- シナリオ名: 現在実行中のシナリオの識別情報
- 記録状態管理: データ記録の開始・停止を制御
- 信号機追跡: 直近の信号機の状態を保持

## privileged_route_planner.py - 特権ルートプランナー

通常の自動運転システムではルート情報は限定的ですが、特権エキスパートはシミュレータから完全なルート情報にアクセスできます。

### 主要データ

- route_waypoints: 経路上の全ウェイポイント
- route_points: 経路上の全座標点
- commands: 各ウェイポイントでの走行コマンド（直進、左折、右折など）
- rotation_angles: 各ウェイポイントでの回転角度

### 事前計算データ

- distances_to_next_traffic_lights: 次の信号機までの距離
- distances_to_next_stop_signs: 次の停止標識までの距離

これらを事前計算しておくことで、毎フレームの計算コストを削減しています。

### shift_route_smoothly()

車線変更時にコサイン補間を使って滑らかな経路を生成するメソッドです。急なステアリング変化を避け、自然な車線変更軌道を作ります。

### extend_lane_shift_transition_for_yield_to_emergency_vehicle()

緊急車両に道を譲るための車線変更遷移を拡張するメソッドです。

### save() / load()

ルートプランナーの状態を保存・復元する機能です。予測（forecasting）処理で、実際の走行を進めずにルート情報を参照する場合に使われます。

## kinematic_bicycle_model.py - 車両予測モデル

車両の将来位置を予測するためのキネマティック自転車モデルの実装です。

### キネマティックモデルとは

動的モデル（タイヤの力やスリップを詳細にモデル化）とは異なり、キネマティックモデルは幾何学的な拘束のみで車両運動を近似します。計算コストが低く、低〜中速域で十分な精度が得られます。

### 状態と行動

- 状態（State）: (x, y, z, heading, speed) の 5 次元
- 行動（Action）: (steer, throttle, brake) の 3 次元

### ステアリングモデル

スリップ角の計算にはアッカーマン幾何に基づく以下の式を使います。

```
slip_angle = arctan(rear_wb / wb * tan(wheel_angle))
```

ここで `rear_wb` は後輪軸までの距離、`wb` はホイールベース、`wheel_angle` は操舵角です。

### 速度モデル

ブレーキとスロットルに異なる多項式モデルを使用します。

- ブレーキ: 7 次多項式
- スロットル: 8 特徴量の多項式

これらはシミュレータ上の実測データから回帰により求められたパラメータです。

### 予測メソッド

- forecast_ego_vehicle(): 自車両の将来軌跡を予測
- forecast_other_vehicles(): 他車両の将来軌跡を予測（ベクトル化により複数車両を同時計算）

## config_expert.py - 設定ファイル

エキスパートの各種パラメータを集約した設定ファイルです。

### データ生成設定

- py123d_data_format: Py123D 形式でのデータ出力設定
- target_dataset: 対象データセット名
- datagen: データ生成に関する全般的な設定

### センサー設定

- num_cameras: 搭載カメラ数
- camera_calibration: カメラキャリブレーション（内部・外部パラメータ）
- lidar_pos: LiDAR の搭載位置
- radar_calibration: レーダーキャリブレーション

### IDM パラメータ

シナリオの種類ごとに、IDM（Intelligent Driver Model）のパラメータが個別に設定されています。

- min_distance: 最小車間距離
- time_headway: 車間時間

対象シナリオ例:
- 停止標識
- 信号機
- 歩行者
- 車両

シナリオごとにパラメータを変えることで、状況に応じた適切な追従行動を実現しています。

### ルート計画設定

- tp_distances: ターゲットポイントまでの距離リスト
- route_planner_min_distance / route_planner_max_distance: ルートプランナーの有効距離範囲

### 天候設定

- shuffle_weather: 天候のランダム切り替え
- jpeg_compression: 天候条件ごとの JPEG 圧縮品質

天候ごとに圧縮品質を変えることで、現実世界のカメラ特性（雨天時のノイズ増加など）を模擬します。

## hdmap/ - BEV マップ生成

`hdmap/` ディレクトリには、Bird's Eye View（上空からの俯瞰図）形式のセマンティックマップを生成するコードが含まれています。

### ObsManager (chauffeurnet.py / obs_manager.py)

OpenDRIVE 形式の道路データから BEV セマンティックマップを生成します。

描画対象クラス:
- 道路表面（road surface）
- 全車線標示（all lane markings）
- 破線車線標示（broken lane markings）

h5py 形式でキャッシュされた静的マップに対し、毎フレームアフィン変換を適用してエゴ車両中心の BEV を生成します。これにより、同じマップの再計算を避けています。

### TrafficLightHandler (traffic_light.py)

信号機に対応する停止線の位置を計算するハンドラーです。信号機の状態と停止すべき位置を関連付けます。

### RunStopSign (run_stop_sign.py)

停止標識の検出と状態追跡を行います。エゴ車両が停止標識に正しく対応したかどうかを記録します。

### birdview_map_opencv.py

CARLA マップから h5py 形式のマップファイルを生成するスクリプトです。OpenCV を使って道路形状を描画し、静的マップとして保存します。

### transforms.py

座標変換ユーティリティです。ワールド座標系とピクセル座標系の間の変換を行います。

---

## scenario_sorter.py - シナリオソーター

アクティブなシナリオをエゴ車両からの距離順にソートするモジュールです。

- 距離が近いシナリオほど優先度が高くなります
- 終了済みシナリオ（アクターが消滅したもの）を自動的に除去します

これにより、エキスパートは最も対応が急がれるシナリオから順に処理できます。

---

## expert_py123d.py - Py123D 統合

`expert_py123d.py` は `Expert` クラスを拡張し、Py123D フォーマットでの構造化データログ出力を実現します。

### Apache Arrow 形式

データは Apache Arrow の列指向フォーマットで保存されます。大規模データの効率的な読み書きに適しています。

### 座標変換

CARLA の座標系から ISO 8855 規格の座標系へ変換を行います。

- 主な違い: Y 軸の反転
- CARLA は左手座標系、ISO 8855 は右手座標系を採用しているためです

### 抽出データ

- エゴ車両の状態（位置、速度、加速度など）
- バウンディングボックス（他車両、歩行者などの 3D 検出枠）
- カメラデータ（RGB 画像、キャリブレーション情報）
- LiDAR データ（3D 点群）

## データ収集の全体フロー

エキスパートによるデータ収集の全体的な流れは以下の通りです。

```
1. CARLA シミュレータがシナリオを開始
2. ExpertBase が記録状態を初期化
3. ExpertData.sensors() でセンサーリグを構成
4. 毎フレーム:
   a. ExpertData.tick() でセンサーデータを順次処理
   b. Expert.run_step() → _get_control() で制御量を計算
   c. ExpertData.save_sensors() で非同期保存キューに投入
   d. 制御量を CARLA に返す
5. シナリオ終了時にデータ保存を完了
```

このパイプラインにより、特権エキスパートが「模範的な運転」を行いながら、そのときのセンサーデータと制御量のペアを大量に収集できます。収集されたデータは、E2E 自動運転モデルの模倣学習（Imitation Learning）の教師データとして使用されます。
